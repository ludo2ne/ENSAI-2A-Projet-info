Instructions

  • Examen écrit
  • Durée : 2 heures
  • Une feuille A4 de notes manuscrites (recto et verso) est autorisée
  • Calculatrice interdite
ImportantÀ lire avant de commencer
  • Vous pouvez répondre aux exercices dans l’ordre de votre choix.
  • Au sein d’un même exercice, les questions ne sont pas nécessairement classées par difficulté croissante.
  • Sauf indication contraire, les questions attendent des réponses courtes.
  • Suivez strictement les consignes. Si une question vous semble ambiguë, indiquez vos hypothèses sur votre copie.
  • Lorsque du code est demandé, respectez les conventions de base du langage (mots-clés, indentation, etc.). Les erreurs de syntaxe dues à l’écriture manuscrite seront tolérées. Si vous ne vous souvenez pas du nom exact d’une méthode Python, vous pouvez utiliser du pseudocode.
  • Sauf demande explicite, la documentation du code n’est pas requise.

Bon courage !

  1. Donnez six exemples de fichiers ou dossiers couramment présents dans un dépôt de projet informatique.
  2. Listez les principaux acteurs impliqués dans un projet informatique.
  3. Qu’est-ce qu’un design pattern ?
  4. Quelles méthodes HTTP correspondent aux opérations CRUD ?
  5. Écrivez une requête HTTP permettant de créer un nouveau Pokemon (nom : Ponyta, type : Fire, niveau : 12) dans https://pokedex-api (choisissez un endpoint approprié).

2 Questions à choix multiple (8 points)

Chaque question peut comporter une ou plusieurs réponses correctes (au moins une réponse est correcte). Réponse correcte : 1 point. Réponse partiellement correcte : au prorata. En cas de réponse incorrecte : 0.

Development tools : quelles affirmations sont correctes ?

  1. pytest est utilisé pour exécuter des test unitaires.
  2. psycopg2 est utilisé pour communiquer avec PostgreSQL.
  3. requests est utilisé pour communiquer avec PostgreSQL.
  4. FastAPI est principalement utilisé pour formater du code source Python.
  5. Le module abc peut être utilisé pour définir des classes abstraites.
  6. Swagger peut être utilisé pour explorer et tester une API.

Pourquoi logging peut-il être préférable à l’utilisation d’instructions print() lors du debugging d’une application ?

  1. Les logs peuvent indiquer le niveau de gravité d’un message.
  2. Les logs peuvent être configurés pour être écrits dans un fichier.
  3. Les logs peuvent fournir des informations sur le moment où un événement s’est produit.
  4. Les instructions print() ne peuvent afficher aucune information sur une erreur.
  5. Logging est uniquement utile lorsqu’une application plante.

Quelles affirmations décrivent de bonnes pratiques pour les test unitaires ?

  1. Un test unitaire doit vérifier un comportement précis.
  2. Les tests doivent être reproductibles.
  3. Un test devrait idéalement être indépendant des systèmes externes.
  4. Un test unitaire doit toujours accéder à la base de données de production réelle.
  5. Les tests peuvent aider à détecter les régressions après une modification du code.
  6. Un test unitaire dépend d’un ordre d’exécution spécifique.

Quelles affirmations concernant les mocks sont correctes ?

  1. Un mock teste toujours l’implémentation réelle du composant qu’il remplace.
  2. Il peut être utilisé pour isoler le code testé de ses dépendances externes.
  3. Un mock permet à un test de simuler des comportements spécifiques d’une dépendance.
  4. Il est uniquement utile lors du test de code qui accède à une base de données.
  5. Un mock est un objet simulé qui remplace un composant réel pendant un test.

Un utilisateur soumet un formulaire pour créer un nouveau player. Quelle séquence représente le mieux le flux d’une requête à travers les couches de l’application ?

  1. DAO → Controller → Service → Database
  2. Controller → DAO → Service → Database
  3. Service → Client → DAO → Database
  4. Controller → Service → DAO → Database
  5. Service → Controller → DAO → Database

Quelles affirmations décrivent les avantages d’une application layered bien conçue ?

  1. Les Controllers devraient contenir la majeure partie de la logique métier.
  2. Chaque couche a une responsabilité spécifique.
  3. Si le database management system (DBMS) change, l’impact peut être plus limité car le code spécifique à la base de données est principalement isolé dans la layer DAO.
  4. N’importe quelle couche peut accéder librement à la base de données et la modifier.
  5. La séparation des responsabilités peut rendre l’application plus facile à lire, debugger et maintenir.
  6. La logique métier est séparée de l’accès aux données et des interactions avec l’utilisateur.

Un utilisateur clique sur un bouton de l’UI (User interface) pour récupérer ses games. Quelles affirmations sont correctes ?

  1. La base de données reçoit directement le clic de l’utilisateur depuis l’UI.
  2. Le frontend envoie une requête HTTP à la backend API.
  3. Le backend traite la requête et demande à la base de données les données nécessaires.
  4. La base de données peut renvoyer des données au backend, qui envoie ensuite une réponse au frontend.
  5. L’UI doit toujours être implémentée dans le backend.
  6. L’API peut être utilisée comme interface entre le frontend et le backend.

Quelles requêtes HTTP sont appropriées pour récupérer toutes les games jouées par le player 96 ?

  1. PUT https://my-awesome-url/game?id_player=96
  2. GET https://my-awesome-url/game?id_player=96
  3. PUT https://my-awesome-url/game/96
  4. GET https://my-awesome-url/player/96
  5. GET https://my-awesome-url/player/69/games
  6. GET https://my-awesome-url/player/96/games

Quelles affirmations sont correctes concernant les environment variables ?

  1. Les variables d’environment peuvent être utilisées pour configurer la connexion à la base de données.
  2. Un mot de passe peut être stocké dans une variable d’environment.
  3. Le fichier .env contenant des secrets ne doit pas être commité dans le remote repository.
  4. Les identifiants de connexion à la base de données devraient de préférence être écrits en dur dans chaque DAO.
  5. L’utilisation de variables de configuration facilite le changement d’environnement.
  6. L’utilisation de variables d’environment signifie que les secrets ne peuvent pas être accessibles par l’application.
